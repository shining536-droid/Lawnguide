## 1. 현재 결과카드가 이미 커버하는 범위 (`ChatResultCard.tsx` 746줄)

요청하신 10개 항목 중 **5개는 이미 화면에 있습니다.** 신규 설계는 나머지 5개에 집중해야 중복이 없습니다.

| # | 요청 항목 | 현재 | 근거 |
|---|---|---|---|
| 1 | 사건 한줄 요약 | ✅ | `result.status_summary` (헤더, L441) |
| 2 | 사실관계 타임라인 | ❌ | 현재 `timeline_steps` 는 **앞으로의 절차**이지 사용자가 겪은 사실이 아님 |
| 3 | 핵심 법률 쟁점 | ⚠️ 부분 | `type_name` + `risk_level` 뿐. 법조문 섹션 없음 |
| 4 | 현재 보유한 증거 | ⚠️ 데이터는 있음, 화면 분리 없음 | `checklist.status === 'has'` + `userExistingDocs` (L286~316) |
| 5 | 부족한 증거 | ⚠️ 동일 | 준비서류 안에 체크 안 된 항목으로 섞여 있음 |
| 6 | 준비서류 체크리스트 | ✅ | 섹션 3, 체크박스 + 답변 자동체크 (L538) |
| 7 | 변호사에게 물어볼 질문 | ❌ | 없음 |
| 8 | 다음 단계 후보 | ✅ | 섹션 2 "지금 할 일" (L480) |
| 9 | 주의사항 | ✅ | 섹션 4 "주의할 점" — `caution`/`do_not`/`important` (L581) |
| 10 | 면책 문구 | ✅ | `result.disclaimer` 폴백 포함 (L667) |
| — | 저장·공유 | ✅ | `window.print()` PDF 저장 + 링크복사, `diagnosis_save`/`diagnosis_share` 계측 |

### 결정적으로 유리한 사실
`answers`(사용자 답변 전체)가 **이미 `ChatResultCard` 에 prop 으로 들어옵니다** (`ChatBot.tsx` L1947). 지금은 서류 자동체크에만 쓰이고 나머지는 버려집니다.

→ **2·4·5·7 은 새 AI 호출이나 백엔드 없이, `answers` + 도메인별 필드 맵만으로 결정론적으로 만들 수 있습니다.** 이게 이 설계의 핵심입니다. LLM 을 붙이면 톤 안전장치(단정형 금지)를 매번 검증해야 하는데, 결정론적 렌더는 그 리스크가 0입니다.

## 2. 공통 리포트 구조 (최종안)

기존 6섹션을 유지하고, **"상담 준비" 블록 3개를 삽입**합니다. 섹션을 10개로 늘리면 모바일에서 스크롤이 죽으므로 기존 섹션에 흡수시키는 쪽을 택했습니다.

```
━━━ 헤더 ━━━━━━━━━━━━━━━━━━━━━━━━━━━
  {도메인} 진단 결과              [위험도]
  {type_name}
  {status_summary}                        ← ① 사건 한줄 요약 (기존)

━━━ ★신규 A. 내가 입력한 사실관계 ━━━━━━  ← ② 사실관계 타임라인
  answers 를 질문 순서대로 "라벨 — 값" 나열
  · 재직기간 — 1년 6개월
  · 미지급 항목 — 야근수당, 연차수당
  · 미지급 기간 — 4개월
  · 퇴사 여부 — 재직 중
  [답변 수정하기]

━━━ ★신규 B. 핵심 법률 쟁점 ━━━━━━━━━━  ← ③ 핵심 쟁점
  · 근로기준법 제56조 — 연장근로 가산수당 50% 이상
  · 근로기준법 제49조 — 임금채권 소멸시효 3년
  (kb/{domain}/legal_facts.json 에서 type_id 별 2~3개 매핑)

━━━ ① 진행 타임라인 (기존, 라벨만 변경) ━━
  "진행 타임라인" → "앞으로의 절차"
  (신규 A와 이름이 헷갈리지 않게)

━━━ ② 지금 할 일 (기존) ━━━━━━━━━━━━━  ← ⑧ 다음 단계 후보

━━━ ③ 준비서류 (기존, 2블록으로 분할) ━━━
  ✅ 이미 갖고 계신 것        ← ④ 보유 증거   (status='has' 또는 answers 매칭)
  ⬜ 아직 없는 것 — 우선순위  ← ⑤ 부족 증거   (미체크 항목, 중요도 순)

━━━ ★신규 C. 변호사에게 물어볼 질문 ━━━━  ← ⑦ 질문 리스트
  1. 제 사안에서 야근수당 입증 책임은 누구에게 있나요?
  2. 재직 중 진정을 넣으면 불이익 가능성은 어떻게 방어하나요?
  3. 소멸시효 3년이 지난 부분은 회수 방법이 없나요?
  4. (공통) 예상 비용과 기간, 승산 판단 근거는 무엇인가요?
  [질문 복사]

━━━ ④ 주의할 점 (기존) ━━━━━━━━━━━━━  ← ⑨ 주의사항
━━━ ⑤ 무료 상담 기관 (기존) ━━━━━━━━━━
━━━ ⑥ 전문가 CTA (기존) ━━━━━━━━━━━━━
━━━ 면책 문구 (기존) ━━━━━━━━━━━━━━━  ← ⑩
```

### 톤 규칙 (CLAUDE.md 준수 필수)
- 신규 B 쟁점은 **"쟁점"으로만 제시**, "귀하는 ~에 해당합니다" 금지. 표기: `근로기준법 제56조 — 연장근로 가산수당 50% 이상`.
- 신규 C 질문은 사용자가 **변호사에게 던지는 문장**이므로 우리가 판단하지 않습니다. 이 섹션은 톤 리스크가 구조적으로 가장 낮아 가치/리스크 비가 가장 좋습니다.
- 신규 A 는 사용자 자기 입력 재출력이므로 판단 0.

## 4. 결과 화면 요약 카드 문구

리포트 상단에 "이걸 갖고 상담 가세요" 라는 프레이밍 한 줄이 필요합니다.

```
📄 이 화면을 저장해서 상담에 가져가세요
   입력하신 사실관계 · 쟁점 · 준비서류 · 물어볼 질문이 한 장에 정리되어 있습니다.
   [PDF로 저장]  [링크 복사]
```

- 위치: 헤더 바로 아래 (현재 PDF 버튼은 하단 L683 에 있어 끝까지 스크롤한 사람만 봅니다 → **상단 중복 배치 권장**)
- "변호사에게 보여주세요" 대신 "상담에 가져가세요": 특정 상담 형태 단정 회피
- 무료 상담 표현 금지 규칙 준수 (변호사 무료 상담 문구 없음)

## 5. PDF / 복사 / 공유 기능 검토

| 기능 | 현재 | 판정 |
|---|---|---|
| PDF 저장 | `window.print()` (L415) + `afterprint` 로 `diagnosis_save` 계측 | **유지.** 서버 PDF 생성(puppeteer 등) 불필요 — Vercel 함수 번들·실행시간 비용만 늘고 사용자 가치는 동일 |
| 인쇄 CSS | 확인 필요 | ⚠️ `@media print` 스타일이 없으면 접힌 섹션(3.6 신청경로는 기본 닫힘)·CTA 배너·헤더가 그대로 찍힙니다. **`print.css` 신설이 실질적으로 가장 필요한 작업** |
| 링크 복사 | `navigator.clipboard` + `diagnosis_share` | ⚠️ **복사되는 URL 이 `window.location.href`** — `/chat?domain=wage` 뿐이라 **열어도 결과가 재현되지 않습니다.** 공유 기능이 사실상 작동하지 않는 상태 |
| 질문 리스트만 복사 | 없음 | 신규 C 에 개별 복사 버튼 권장 (변호사에게 카톡으로 보내는 실제 행동) |
| 결과 URL 영속화 | 없음 | answers 를 압축해 쿼리(`?a=base64`)로 넣으면 서버·DB 없이 재현 가능. 단 **사건 내용이 URL 에 들어가므로 PII·로그 노출 리스크** → 링크 공유는 차라리 접고 PDF 에 집중하는 쪽이 안전 |

**결론**: PDF(인쇄 CSS) > 질문 복사 > 링크 공유. **링크 공유는 지금 깨져 있으므로 고치거나 버튼을 내리는 판단이 먼저** 필요합니다.

## 6. 구현 우선순위

| 순위 | 작업 | 근거 | 규모 | 데이터 신규 필요 |
|---|---|---|---|---|
| **1** | 준비서류를 "갖고 있는 것 / 아직 없는 것" 2블록 분할 | 데이터 이미 있음(`status`, `userExistingDocs`). 리포트의 핵심 가치를 렌더 한 번으로 얻음 | 소 (`ChatResultCard` 섹션3만) | 없음 |
| **2** | 신규 A "내가 입력한 사실관계" | `answers` 이미 prop. 라벨 맵만 필요 | 소~중 | 도메인별 field→라벨 맵 |
| **3** | `@media print` 인쇄 스타일 | PDF 저장이 이미 계측되는 주요 행동인데 출력물 품질 미검증 | 소 | 없음 |
| **4** | PDF 버튼 상단 중복 배치 + 요약 카드 문구 | 하단 버튼은 완주자만 봄 | 극소 | 없음 |
| **5** | 신규 C "변호사에게 물어볼 질문" | 차별화 최대 · 톤 리스크 최소. 단 도메인×type_id 별 질문 세트 작성 필요 | 중 | 도메인별 질문 3~4개 × type |
| **6** | 신규 B "핵심 법률 쟁점" | `kb/{domain}/legal_facts.json` 을 type_id 에 매핑해야 함. **런타임 fs 읽기 금지** → 빌드타임 상수 사전생성 필수 | 중~대 | 매핑 + 생성 스크립트 |
| **7** | 링크 공유 수정 또는 제거 | 현재 깨져 있음. PII 때문에 "고친다"가 정답인지 자체가 미결 | 판단 필요 | — |
