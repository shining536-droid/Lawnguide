## 1. 현재 상태 실측 (`web/src/app/chat/page.tsx`)

요청하신 5개 요소 중 **2개는 이미 구현되어 있습니다.**

| 요청 요소 | 현재 | 위치 |
|---|---|---|
| 1. 상단 헤드라인 | ❌ **없음** | — |
| 2. 보조 문구 | ❌ **없음** | — |
| 3. 신뢰 배지 | ✅ 4개 있음 — `31개 분야` / `평균 3분` / `무료 · 회원가입 없음` / `입력 정보 저장 안 함` | L112~126 |
| 4. 예시 질문 6개 | ✅ 있음 — fraud/dismissal/divorce/wage/jeonse/traffic-accident | `EXAMPLE_QUESTIONS` L11~18 |
| 5. 결과 예시 카드 | ❌ **없음** | — |

즉 실제 갭은 **헤드라인 / 보조문구 / 결과 예시 카드 3개**입니다. 배지·예시질문을 새로 만들면 중복이 됩니다.

### 현재 첫 화면의 실제 문제

1. **문맥 없는 배지가 먼저 온다.** 사용자가 `/chat?domain=wage` 로 블로그에서 넘어오면 제일 위에 뜨는 게 "31개 분야"라는 규모 자랑입니다. "무엇을 해주는 곳인지"가 어디에도 없습니다.
2. **`showWelcome = !searchParams.domain`** — 블로그 CTA 는 전부 `?domain=` 을 달고 오므로 **블로그 유입자는 환영 섹션(배지·예시질문)을 아예 못 봅니다.** 바로 질문 화면입니다. 즉 지금 만들어 둔 신뢰 요소가 정작 가장 중요한 유입 경로에 노출되지 않습니다. ← **이번 건의 최대 발견**
3. 결과물의 모습을 모른 채 질문에 답해야 한다 → 3~8문항 이탈.
4. `metadata.robots.index: false` — 의도된 설정(중복·저품질 색인 방지). 유지.

## 2. 개선안 문구

### 헤드라인 (H1)
```
변호사 상담 전, 내 상황을 먼저 정리하세요
```
- "AI로"를 헤드라인에서 뺀 이유: CLAUDE.md CTA 규칙에 "AI 는 포함하되 문장 맨 앞 반복 금지". 보조문구에서 받습니다.
- 판단형 금지 원칙 준수 — "진단해드립니다" / "받을 수 있는지 알려드립니다" 안 씀.

### 보조 문구
```
질문 3~8개에 답하면 핵심 쟁점·준비서류·아직 부족한 자료를 정리해드립니다.
상담 시간을 아끼고, 무엇을 물어볼지 미리 챙길 수 있습니다.
```
- "상담 시간을 줄이고"를 "아끼고"로: 짧은 상담이 좋다는 오해 방지.
- "부족한 증거" → "아직 부족한 자료": 증거 단정 회피.

### 신뢰 배지 (기존 4개 + 1개 추가, 순서 변경)
```
무료  ·  회원가입 없음  ·  입력 정보 저장 안 함  ·  평균 3분  ·  31개 법률 분야
```
- 순서를 **거부감 제거 → 비용(시간) → 규모** 로 뒤집습니다. 현재는 규모가 먼저입니다.
- `31개 분야` → `31개 법률 분야` (분야가 무엇의 분야인지 명시)

### 도메인 진입 시 문맥 헤드라인 (`?domain=wage`)
현재는 아무 문구 없이 질문이 시작됩니다. 도메인별 한 줄을 추가:
```
임금 문제 — 상담 전 정리를 시작합니다
아래 질문에 답하면 지금 챙길 자료와 절차를 정리해드립니다.
```
`DOMAINS` 배열의 `name` 을 그대로 써서 도메인 31개용 문구를 따로 만들지 않습니다.

## 4. 컴포넌트 구조 제안

```
web/src/app/chat/page.tsx                (수정)
└─ <ChatEntryHero domain={searchParams.domain} />   ← 신규, 서버 컴포넌트
   ├─ 1. <h1> 헤드라인            domain 없을 때: 범용 / 있을 때: "{도메인명} — 상담 전 정리를 시작합니다"
   ├─ 2. <p>  보조문구
   ├─ 3. TrustBadges              현재 page.tsx L112~126 을 이 안으로 이동 (중복 제거)
   ├─ 4. ExampleQuestions         현재 EXAMPLE_QUESTIONS 를 이 안으로 이동. domain 있을 때는 숨김
   └─ 5. <ResultPreviewCard />    ← 신규, 정적 마크업. ChatResultCard 재사용 금지(무거움)
```

### 왜 `ChatResultCard` 를 재사용하지 않는가
`ChatResultCard.tsx` 는 746줄 클라이언트 컴포넌트에 `useState`·`window.print`·`gtag` 발사(`chat_complete`)가 묶여 있습니다. 첫 화면에 마운트하면 **`chat_complete` 이벤트가 진단도 안 했는데 발사되어 퍼널 지표가 전부 오염됩니다.** 예시 카드는 별도의 순수 정적 컴포넌트로 만들어야 합니다.

### 핵심 구조 변경 — `showWelcome` 조건
```tsx
// 현재 — ?domain= 유입자는 신뢰요소를 전혀 못 봄
const showWelcome = !searchParams.domain;

// 변경안 — 항상 히어로는 보여주고, 안쪽 요소만 분기
<ChatEntryHero domain={searchParams.domain} />
//   내부: 헤드라인·보조문구·배지 = 항상 표시
//         예시질문 6개 + 결과 예시카드 = domain 없을 때만 (질문 화면과 경쟁 방지)
```
`?domain=` 유입자에게도 최소한 **헤드라인 + 배지**는 보이게 하는 것이 이번 변경의 실질 효과입니다.

## 6. 추가 검토 필요한 부분

1. **`/chat` 은 `robots: index:false`.** 따라서 이 페이지의 개선은 SEO 가 아니라 **유입 후 전환** 만 움직입니다. GSC 에서 효과가 안 보이는 게 정상이므로, 판정은 GA4 `chat_start → chat_complete` 완주율로만 해야 합니다. 현재 그 비율을 아직 한 번도 읽지 않았습니다 → **개선 전 베이스라인 측정이 먼저**입니다.
2. **`loadSubtypesData()` 의 런타임 fs 읽기** (`chat/page.tsx` L52~70): `path.join(process.cwd(), '..', 'domains', 'chat-config')` 를 `fs.readFileSync` 로 읽습니다. CLAUDE.md 가 금지한 2026-04-26 procedure-data 사고와 **정확히 같은 패턴**입니다. 대상이 `kb/`(405MB) 가 아니라 `domains/`(2.1MB) 라서 지금은 터지지 않고 있을 뿐입니다. 또한 `process.cwd()` 상위 디렉터리 참조는 Vercel 배포 환경에서 경로가 달라질 수 있어 `catch` 로 조용히 삼켜지면 subtypes 가 통째로 비게 됩니다. → **별건으로 `generate-procedure-data.mjs` 방식(빌드타임 TS 상수 사전생성)으로 전환 권장.** 이번 C 작업과 독립.
3. **예시 질문 도메인 편중**: 6개 중 노동 2(dismissal, wage) + 비노동 4. `EXAMPLE_QUESTIONS` 에 `unemployment`(스포크 309개 보유, 검색수요 최상위)가 없습니다. 교체 후보.
4. **A/B 없이 한 번에 바꿀지**: `/chat` 은 전환 최종 관문이라 되돌리기가 쉬워야 합니다. 배포 후 7일 `chat_start→chat_complete` 비교로 판정하되, 같은 기간에 네이버 발행량이나 CTA 빈도를 같이 건드리면 원인 분리가 안 됩니다. **다른 실험과 겹치지 않는 주에 단독 배포**를 권합니다.
