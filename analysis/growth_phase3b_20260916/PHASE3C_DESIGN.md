# PHASE3C_DESIGN — 공통 링크 블록 축소 실험 (설계만, 실행하지 않음)

**지금 실행하지 않는다.** 3B 가 "본문 리프레시 + 문맥 내부링크"의 효과를 보는 실험이므로, 템플릿 변경을 섞으면 두 효과를 분리할 수 없다. 3B 판독(배포 +28일) 이후에 별도 승인을 받아 진행한다.

## 1. 문제 (Phase 3A 관찰)

`app/guide/[domain]/[slug]/page.tsx` 의 추천 블록이 다음과 같이 동작한다.

- 같은 도메인 top3 + 교차 클러스터 2개를 **`Math.random()`** 으로 고른다 → 빌드할 때마다 링크 구성이 바뀐다
- `<details>` 안에 **같은 도메인의 나머지 스포크를 전부** 나열한다 (unemployment 는 300개 이상)

결과적으로 큰 도메인 페이지는 렌더된 가시 텍스트의 **90~95%가 링크 목록**이고, 본문은 4.6~10%에 불과하다(예: assault 페이지 39,877자 중 본문 4.6%). 도메인 내 모든 페이지가 거의 같은 링크 목록을 갖는다.

## 2. 가설

거대한 공통 링크 목록이 (a) 페이지 간 차별성을 희석하고 (b) 크롤러가 보는 "이 페이지 고유 콘텐츠" 비중을 떨어뜨려 색인·평가에 불리하게 작용한다.

## 3. 설계

- **단위**: 도메인 1개 (예: `unemployment` 308페이지). 전역 적용 금지.
- **처치**: 해당 도메인에서만
  - `<details>` 전체 목록 → **의미상 관련 10개**로 축소
  - `Math.random()` → **결정적 선택**(슬러그 해시 기반)으로 교체해 빌드마다 링크가 흔들리지 않게 함
  - 본문 문맥 링크는 그대로 유지
- **대조**: 규모·성격이 비슷한 다른 도메인 1개(예: `retirement` 262페이지)는 변경하지 않음
- **제외**: 3B 실험 대상 40개 페이지가 포함된 도메인은 3B 판독 전까지 처치 대상에서 제외

## 4. 측정

| 구분 | 지표 |
|---|---|
| 주 | 처치 도메인 vs 대조 도메인의 **색인 페이지 비율 변화**(GSC), 도메인 단위 Naver·Google 유입 |
| 보조 | 페이지당 렌더 가시 텍스트 중 본문 비중, 평균 페이지 용량, 크롤 빈도(GSC 크롤 통계) |
| 기간 | 배포 후 28일, 필요 시 56일 |

도메인 단위 비교라 무작위 배정이 불가능하다. 따라서 **인과 주장 강도는 3B 보다 약하며**, 사전·사후 추세와 대조 도메인 동시 비교로만 해석한다.

## 5. 위험과 안전장치

- 내부링크 감소로 **크롤 경로가 줄어들 수 있다** → 허브 페이지는 전체 목록을 유지해 발견 경로를 보존
- 기존 유입 페이지의 순위 변동 위험 → 처치 도메인에서 상위 유입 페이지는 별도 모니터링
- 되돌리기: 템플릿 변경 1건이므로 revert 로 즉시 원복 가능

## 6. 함께 검토할 후속 항목 (3C 와 별개)

- `industrial-accident` 55개 페이지가 `DOMAINS` 누락으로 **noindex 404 렌더** (Naver 회수 실험 감사에서 발견). 실험과 무관한 명백한 버그이므로 우선 처리 대상.
- 같은 주제 클러스터(배우자 발령 5개, 1년 미만 퇴직금 5개, 5인 미만 퇴직금 4개, 근로자성 임원 7개) 통합 — GSC 노출 확인 후.
