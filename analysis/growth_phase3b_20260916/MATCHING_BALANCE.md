처음에는 "매칭 비용이 싼 20페어만 채택" 을 썼는데, 그러면 트래픽이 큰 페이지(207·191·173·128·127·109 세션)가 전부 탈락한다 — 트래픽이 클수록 짝을 찾기 어려워 비용이 높기 때문이다. 실험의 검정력과 대표성이 무너져서 규칙을 바꿨고, 바꾼 시점은 **배정 결과를 보기 전**이다.

## 2. 매칭 비용 함수 (사전 처치 변수만 사용)

```
cost(a,b) = 1.0·|log(1+cur_a) − log(1+cur_b)|
          + 0.6·|log(1+prev_a) − log(1+prev_b)|
          + 0.8·|pretrend_a − pretrend_b|          (pretrend = log((cur+1)/(prev+1)))
          + 0.35·[도메인 다름]
          + 0.05·[스포크 type 다름]
```

탐욕적 전역 매칭: 남은 후보 중 비용이 가장 낮은 쌍을 반복 선택(결정적). 페어별 비용은 `experiment_manifest.csv` 의 `eligibility_notes` 에 기록했다.

- 페어 비용 중앙값 0.42, 최소 0.09, 최대 1.47
- 비용이 큰 2개: P02 (1.473, 부동산매매 128 ↔ 실업급여 191), P01 (0.919, 교통 207 ↔ 실업 173). 트래픽 최상위 4개는 서로밖에 짝이 없어 도메인을 넘겨 매칭했다 — 같은 도메인 강제는 오히려 트래픽 매칭을 망친다는 사양에 따른 것이다.

**pretrend 이질성 (양쪽 arm 모두 상승·하락 혼재 — 사양 요구사항 충족)**

## 4. 재무작위화 규칙 (사전 지정)

다음 중 하나에 해당할 때만 1회 재무작위화하고 그 사실을 이 문서에 기록한다.
- 현재/직전 세션 log 기준 SMD 의 절대값이 0.25 초과
- pretrend SMD 의 절대값이 0.25 초과
- 한쪽 arm 에 특정 도메인이 14개(70%) 이상 몰림

이번 배정은 세 기준 모두 통과했으므로 **재무작위화하지 않았다.** "결과가 불편해 보인다"는 이유로는 재배정하지 않는다.
